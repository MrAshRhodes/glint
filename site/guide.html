Install

Glint needs macOS 14 or later. Release downloads are universal: they include Apple silicon and Intel builds.

With Homebrew

If you already have Homebrew, run:

brew install --cask MrAshRhodes/tap/glint

This adds the tap if needed and installs Glint in Applications.

With a download

Open the latest release. Download Glint-<version>.zip and its matching Glint-<version>.zip.sha256 from the same release. For a DMG instead, download Glint-<version>.dmg and Glint-<version>.dmg.sha256. Keep the pair in the same folder without renaming either file.

Before extracting the ZIP or opening the DMG, open Terminal and change to that folder (for example, cd ~/Downloads). Replace <version> with the downloaded release's version and run only the command for your chosen format:

ZIP:

shasum -a 256 -c "Glint-<version>.zip.sha256"

DMG (instead of ZIP):

shasum -a 256 -c "Glint-<version>.dmg.sha256"

Continue only if the command succeeds and reports Glint-<version>.zip: OK (or Glint-<version>.dmg: OK). If verification fails for any reason, including a mismatch or a missing archive or checksum, stop. Do not install the app or clear quarantine. Download the matching pair again from the official release and verify again.

After successful verification, extract the ZIP or open the DMG and move Glint.app to Applications. A matching checksum confirms agreement with the published checksum; it is not notarization or proof that the app is safe.

Signing status: Glint releases are signed with the project's own certificate, so macOS keeps Screen Recording permission across updates. They are not Apple-notarized, so macOS may block a manual download. The Homebrew cask removes this app's quarantine flag, bypassing its Gatekeeper quarantine check. Only install if you trust the project and its release. Do not ignore a malware warning.

For a manual download, consult Apple's guidance on opening apps safely. You can also build Glint yourself from the source below.

Update Glint

Glint does not automatically download or install updates. Choose Check for Updates… from the menu bar, or use the button in Preferences → About. This contacts GitHub to compare your installed version with the latest stable release.

If you installed with Homebrew

  1. Save any open edits and quit Glint.
  2. Run the command below.
  3. Open Glint from Applications again. Check the version in About Glint.
brew update && brew upgrade --cask glint

brew update refreshes Homebrew and its taps; it does not install a newer Glint. The brew upgrade part does that. Keep using Homebrew for an app it manages rather than replacing the app manually.

If Glint reports a new release but Homebrew says it is already current, the tap may still be catching up. Try again after the release's tap update has finished. You can inspect the available version with brew info --cask glint.

If you installed from a ZIP or DMG

  1. Save your edits and quit Glint.
  2. Download the new release from GitHub, including the ZIP or DMG and its matching .sha256 file.
  3. Follow the manual-download verification steps before extracting the ZIP or opening the DMG. Continue only if verification succeeds and reports OK.
  4. Replace Glint.app in Applications with the verified new copy, then reopen it.

Replacing the app keeps your separately stored preferences, presets and image files. Do not delete those folders to update.

After an update: every release is signed with the same certificate, so Screen Recording permission carries over. Updating from 1.2.0 or earlier is the one exception: those releases were ad-hoc signed, so macOS needs the permission once more. Choose Re-authorize Screen Recording… in Preferences → About (Glint also opens its setup window if a capture fails for lack of access), allow Glint in System Settings, then relaunch Glint. Later updates keep the permission.

Permissions

Screen capture requires Screen Recording access. In System Settings → Privacy & Security, find Screen Recording (called Screen & System Audio Recording on some macOS versions), enable Glint, and relaunch if asked. Preferences → About shows whether access is enabled. If capture fails even though Glint looks enabled, see Troubleshooting.

Open existing images with Open Image… or ⌘ O; screen access is not needed just to style an image file.

Capture

Use the menu bar icon to capture an area, a window or the full screen. Capture with Timer gives you 3, 5 or 10 seconds to get ready. Repeat Last Area captures the same region again.

Default shortcuts use Control + Option + Command:

Default capture shortcuts
ShortcutAction
⌃⌥⌘ 4Area, open in editor
⌃⌥⌘ 5Area, copy to clipboard
⌃⌥⌘ 6Window
⌃⌥⌘ 3Full screen
⌃⌥⌘ 7Text recognition (OCR) to clipboard
⌃⌥⌘ RRepeat last area

Cancel a selection with Esc. Change the shortcuts in Preferences if another app uses the same combination.

Snap selection to edges

Enable Snap to Edges in the menu bar or Snap selection to edges in Preferences → Capture. These controls share one saved setting, are off by default, and reset to off with Reset all preferences. The menu checkmark and Preferences switch stay in sync.

While selecting an area, the anchor and moving corner can align to nearby visible window bounds or display edges. Guides show the active alignment, and the captured rectangle is the one shown in the preview. This also applies to area-to-clipboard, Capture Text and timed area selection. The selection stays on the display where the drag began.

Hold ⌘ to temporarily invert the setting: with snapping off, hold to snap; with it on, hold for free selection. Releasing the key restores the saved setting, even without moving the mouse. The overlay hint shows the current state. Shift-drag still makes a square; Shift-arrow still nudges by 10 points. Space switches area/window mode, Return confirms, and Esc or right-click cancels.

Targets are sampled when the overlay opens. Restart selection if another window moves. Snapping uses rectangular window bounds, not shadows, rounded contours, controls, cards or images inside a window. Arbitrary visual-content detection is not enabled, and snapping does not take an extra screen image or request Accessibility permission.

Style your image

Start with a preset, then adjust the background, padding, inset, corner radius and shadow. Choose an aspect ratio for the destination, or keep the natural image proportions. You can also rotate, flip, add perspective, apply a window frame or add a watermark.

Auto-balance looks for uniform image borders and balances the margins. It works best on screenshots with clear, flat surrounding space.

The backgrounds include gradients, mesh gradients, patterns, solids and transparency. A custom image is also supported.

Use your desktop wallpaper

Check Use desktop wallpaper under Background. Glint reads the system wallpaper image directly, without a file picker. It never captures desktop icons, windows or other desktop content for the background. The image fills the canvas, cropping at the edges when needed; padding, shadows, rounded corners, frames and other styling still work.

Glint uses the wallpaper macOS reports for the main display (the display with the primary menu bar), in its current Space, even when the capture or editor is on another display. It keeps that image fixed in the editor so preview and export use the same wallpaper. Toggle the checkbox off and on to refresh after changing wallpapers or Spaces.

Dynamic wallpapers: Glint uses the image file's primary still, which may differ from the time-of-day or animated scene currently on your desktop. For rotating wallpapers, it uses the current image if macOS supplies an image file. If macOS supplies only a folder, no readable file, or an unsupported wallpaper, Glint explains the problem and uses your normal background instead.

Uncheck the option to restore your previous background, or choose any normal background control to switch away from wallpaper. The option is remembered in your editor settings and saved presets; a preset resolves the current wallpaper rather than storing a copy of it. Direct capture exports and command-line renders use the same rule and report a warning if they need to fall back.

Annotations

Use arrows and lines to point things out, rectangles and ellipses to frame an area, and pen or highlighter to draw freely. Add text and numbered counters for instructions.

Select an annotation to change its styling or layer order. Undo and redo let you revise without starting over. Use Solid or Pixelate redaction, rather than blur or a translucent highlighter, for private information.

Redaction & privacy

The Redact / Obfuscate tool starts with plain Solid redaction for every image. Click the current-style label (Solid, Blur, or Pixelate) to open its menu and choose a style. The menu also supports keyboard focus and standard menu navigation. Clicking the Redact icon or pressing 3 activates the tool without changing its style. Drag to cover the private region.

Solid and Pixelate replace covered pixels completely. Solid offers plain fill or a checkerboard in the inspector; choose both pattern colours and the tile size. Pixelate uses an opaque decorative mosaic whose tiles and colours never come from the sensitive image. Toggle its colour highlight to add the selected solid redaction colour as an accent while keeping the mosaic visible. Both styles remain fully opaque regardless of colour alpha or annotation opacity.

Blur is obfuscation, not secure redaction. Information may be recoverable from this effect, so it is unsafe for secrets. The editor warns when you use or select Blur. Manual mode and appearance options are not remembered for the next image.

Preview, saved files, clipboard images, shared images and the copies Glint keeps for Reopen Last Image use the same replacement style and colours. Exported images are flattened: they do not contain editable redaction layers or an embedded original. You can still undo edits while the editor is open; your original image and any separately saved raw capture are not erased.

Optional Auto-redact uses on-device text recognition to find patterns such as email addresses, phone numbers, credit card numbers, IP addresses and common API tokens. It is off by default and always uses solid fill, regardless of the manual mode. You can choose detection categories, custom words and the solid color, but not blur or pixelate.

Review before you share. Detection is not a guarantee and can miss information. Use Solid or Pixelate redaction for sensitive details and inspect the exported image. If raw history is enabled, the untouched capture may still contain the information you removed from the styled output.

Glint does not upload your screenshots. The manual update check contacts GitHub; opening web links or sharing an image uses the destination you select.

Presets

Glint starts with Default, Clean, Social 16:9 and Transparent. Apply one, adjust the look, then save your own preset for reuse. Set a default in Preferences → Presets.

With Remember settings checked in Preferences → Editor, new screenshots start with your last-used settings, including after you restart Glint. Uncheck it to start every screenshot from the default preset. Remembering never changes a saved preset, so save a preset for any look you want to return to.

You can also create a preset without a capture. In Preferences → Presets, choose Add Preset…. Pick a starting point from the live previews on a built-in sample image: your last-used settings, a saved preset, or a built-in preset you deleted. Name it and choose Add, or choose Customize in Editor… to open the Preset Designer. It offers the look controls without annotations or exports. Choose Save Preset (⌘ S), optionally with Set as default. Use My Image… previews your own image instead; the image is never saved in the preset. Designing a preset does not change your last-used editor settings.

To change a saved preset, select it and choose Edit…. Saving updates it in place, including a new name, and a default preset stays the default.

The homepage light table shows actual output from these presets using original terminal and dashboard artwork. Choose a subject and finish, or switch to Original to compare the untouched image. It is a renderer demonstration, not the app's editor, and does not upload or edit your images in the browser.

Export & folders

Save PNG, JPEG, HEIC or TIFF at 1× or 2× scale. PNG is a good choice for crisp text and transparent backgrounds. You can also copy to the clipboard, use the share sheet, or drag the result into another app.

Preferences → Output controls the save folder, naming and history. The default save folder is Desktop; capture history uses ~/Documents/Glint, with Raw and Output subfolders. These locations are configurable.

The default filename template is Glint-{datetime}. The menu's Show Output Folder and Show Raw Folder actions take you to the history folders. To get back an image you only copied or dragged and never saved, see Reopen Last Image.

Copying normally closes the editor. Disable Close editor after copying in Preferences if you want to keep adjusting the image.

Reopen Last Image

Choose Reopen Last Image in the menu bar icon's menu, right after Open Image… and Open Recent, or in the File menu, to open the latest image Glint kept for you. It works for an image you only copied or dragged into another app and never saved, so you can get it back after the clipboard changes, the editor or quick-access thumbnail closes, or you restart Glint. The item is dimmed when there is nothing to reopen.

This is opt-in. Turn on Keep copied and dragged screenshots for reopening in Preferences → Output; it is off by default. Until you do, Glint copies, drags and saves exactly as before: it keeps no extra images, writes no extra files and removes nothing, including right after an update.

With the setting on, Glint keeps the finished image each time you:

  • copy it with Copy ⌘C in the editor;
  • capture straight to the clipboard, for example with ⌃⌥⌘ 5, or let Copy to clipboard in Preferences → Output copy each capture automatically;
  • drag it out with the editor's Drag to share tile or the quick-access thumbnail.

What Glint keeps is the finished image that was copied or dragged, with your styling, annotations and redactions already applied. It never keeps the original capture, and if an image cannot be rendered, nothing is copied, dragged or kept. Kept images are saved in the Output folder (the Output subfolder of your history folder) using your export format, scale and file name template. Copying or dragging the same unchanged image again reuses its file rather than saving another. If Glint cannot keep an image, for example because the folder is not writable, it tells you in a notification; the copy or drag itself still goes through.

If you quit while Glint is still keeping a screenshot, it waits up to three seconds for saving to finish. If it needs longer, Glint stays open and notifies you rather than losing the screenshot. Try quitting again once saving has finished.

It fits alongside your other Output settings:

  • Keep history is required. When it is off, the setting is dimmed and Glint pauses keeping images and cleanup; it never turns history on for you. Your choices apply again when you switch Keep history back on.
  • Save styled output: if it already saved the finished image to the Output folder, Glint reuses that file instead of adding a duplicate, and the file also counts for Reopen Last Image and cleanup.
  • Save untouched raw capture stays independent. This feature never touches the Raw folder, and a raw capture is not a substitute for Reopen Last Image because it has none of your edits. As before, a raw capture may still contain information that you redacted from the finished image.
  • Save and Save As are unchanged. Files you save yourself go where you choose and are never kept, tracked or removed by this feature.
  • Dragging from the editor still uses a temporary file that is removed when the editor closes. The image Glint keeps is a separate file in the Output folder.

Reopen Last Image opens the kept image in the editor as a finished, flattened image. Glint does not apply your preset, frame, background, padding or shadow again, and it does not run Auto-redact again, because all of that is already part of the image. Earlier annotations and redactions are no longer separate layers, so you cannot edit or undo them. You can still add annotations, then copy, save or drag the result. Anything you change in that session, such as adding a background, is not remembered for your next screenshot. Kept images also appear in Open Recent and open the same way. If a kept image has since been removed, has expired or cannot be read, Glint says so and forgets it.

Remove old screenshots automatically

By default Glint never removes anything from the Output folder. To let kept images expire, choose a period in Keep screenshots in Output for (Preferences → Output): Forever (the default), 1 day, 7 days, 30 days or 90 days. Cleanup is deliberately narrow:

  • It only considers images Glint itself saved after you opted in, by turning on the setting above or choosing a finite period. Glint lists them in a hidden .glint-output-index.json file in the Output folder, and files that are not listed there are never removed.
  • Expired images are moved to the Trash, not deleted permanently, so you can put them back until you empty it. Age counts from when Glint last kept the image, so copying or dragging the same image again renews it. If an image cannot be moved, it stays where it is and Glint tells you.
  • It never removes anything in Raw; images you saved yourself with Save, Save As or an export; files that were already in the Output folder before you opted in; files you edited or replaced after Glint saved them; folders or symbolic links; or an image being dragged at that moment (it is skipped and checked again later).
  • It runs in the background shortly after Glint starts, about every six hours, and a short while after you change the setting, so a misclick never removes anything instantly.
  • It follows Keep history and the current Output folder. Nothing is removed while history is off, and if you change the history folder, images left in the old one are not touched.

To go back, choose Forever, or use Reset all preferences in Preferences → General, which turns both settings back to off and Forever.

Preferences

Open Preferences with ⌘ ,. General controls launch at login, menu bar and Dock visibility, sounds and notifications. Capture controls cursor visibility, remembering the last area, selection snapping and hiding Glint windows during capture.

Output controls capture actions and files, including whether Glint keeps copied and dragged screenshots for reopening and for how long (see Reopen Last Image). Editor controls the default preset, Remember settings, auto-balance and auto-redact. Presets adds, edits, renames, deletes, imports and exports presets and sets your default look; see Presets. About shows the version, Screen Recording permission (with Re-authorize Screen Recording…) and manual update check.

Automation

URL scheme

With Glint installed, another app or script can open these URLs:

glint://capture-area
glint://capture-window
glint://capture-fullscreen
glint://capture-text
glint://repeat-last
glint://preferences
glint://preset?name=Clean
glint://open?file=%2FUsers%2Fyou%2FDesktop%2Fimage.png

Percent-encode spaces and other special characters in query values. From Terminal, use open 'glint://capture-area'. Capture actions still require screen permission.

Every capture URL also requires confirmation in Glint, including Capture Text and Repeat Last Area. Nothing is captured, saved or copied until you choose Allow Capture. Cancel leaves the screen uncaptured. Approval applies to that request only; there is no “always allow” option, so capture URLs cannot run unattended. After approval, your normal capture settings apply, including raw history and clipboard output where enabled.

Capture URLs received while confirmation or capture is in progress are rejected rather than queued; send a new request afterward. Menu and hotkey captures do not gain an extra prompt. Opening images, choosing presets, opening preferences and command-line rendering are unchanged.

Command-line rendering

/Applications/Glint.app/Contents/MacOS/Glint \
  --render input.png output.png \
  --preset "Social 16:9" --scale 2

/Applications/Glint.app/Contents/MacOS/Glint --list-presets
/Applications/Glint.app/Contents/MacOS/Glint --version
/Applications/Glint.app/Contents/MacOS/Glint --diagnose

Use --help for the command reference. The output extension selects the file format. These commands operate on local files; they do not upload an image.

--diagnose checks Screen Recording permission without requesting access and prints only permission state, aggregate display/window/application counts, and fixed status messages. It does not print window titles, app identities, process/window/display identifiers, or per-display details. Aggregate counts still describe your desktop activity, so review reports before sharing.

Troubleshooting

Capture is blocked or stopped after an update

Choose Re-authorize Screen Recording… in Preferences → About, even if Glint still looks switched on under Screen Recording; Glint also opens its setup window if a capture fails for lack of access. It clears Glint's old entry in the permission list, the same as running tccutil reset ScreenCapture io.github.mrashrhodes.glint, and requests access again. Allow Glint in System Settings, then relaunch Glint. If macOS cannot reset the old entry, Glint explains how to remove it and add it back manually. This is needed once when updating from 1.2.0 or earlier; later updates keep the permission.

I cannot find the app window

Glint is a menu bar app. Look for its icon near the clock. Capture a region or choose Open Image… to open an editor.

Reopen Last Image is dimmed

It is dimmed when Glint has no kept image to open. Keeping images is opt-in: turn on Keep copied and dragged screenshots for reopening and Keep history in Preferences → Output, then copy or drag the image again. An image copied or dragged before you opted in cannot be recovered. A kept image also leaves the menu after you delete it, after it expires under Keep screenshots in Output for, or when you switch to a different history folder, because Glint only looks in the current Output folder. See Reopen Last Image.

Homebrew does not offer the release yet

Run brew update, then brew info --cask glint. The cask must be updated after the release publishes. Check the tap if the displayed version is behind.

Something else is wrong

Check existing issues or report the problem with the steps, macOS version and Glint version. Review --diagnose output for private information before including it.

Build from source

Install Xcode or the Apple Command Line Tools with a compatible Swift toolchain, then:

git clone https://github.com/MrAshRhodes/glint.git
cd glint
make test
make app

The app is written to dist/Glint.app. Use make universal for both architectures. Read the contributor guide for toolchain details and release instructions.
